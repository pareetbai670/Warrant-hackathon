      How it works

      Four steps between an idea and a tool call.

      1. 1

        Propose

        An agent states the tool it wants, the arguments, and where the instruction came from: the user's task or something it read along the way.

      2. 2

        Check

        The gate tests provenance, destination, spend limit and reversibility. Outside text can never grant itself authority.

      3. 3

        Warrant

        Safe actions get a signed, single-use slip with a scope and an expiry. Risky ones wait for a human to countersign.

      4. 4

        Record

        Every outcome, including refusals, is chained into the ledger. Rewrite one line and verification points at it.

      After the hackathon

      From demo to drop-in gate.

      • MCP proxy. Put Warrant in front of any MCP server so existing agent stacks adopt it without code changes.
      • Real signing. Ed25519 keys held in a hardware-backed signer, with per-agent identities.
      • Policy as code. Write rules in Cedar or Rego, test them against recorded ledgers before shipping.
      • Public anchoring. Publish ledger roots to a transparency log so even the operator cannot rewrite history.
